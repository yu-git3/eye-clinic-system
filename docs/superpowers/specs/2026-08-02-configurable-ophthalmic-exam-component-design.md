# 可配置眼科检查录入组件设计

## 目标与范围

通过“临床指标定义＋检查模板定义”驱动统一的眼科检查录入组件，使检查模板能够复用于档案基线、专科病历和后续治疗复查。第一阶段以眼健康检查为复杂医生查体模板验证快速录入、结构化存储、描述生成和门诊病历回传；角膜地形图、医学验光等继续复用同一组件框架。

## 配置模型

### 临床指标定义

维护指标编码、名称、数据类型、眼别、单位、参考范围、枚举值、外部映射和状态。指标是最小结构化数据项，不包含具体业务场景。

### 检查模板定义

检查模板选择多个指标并维护顺序，类型分为“医生查体”和“医技检查”。

医生查体模板增加以下配置：

- 指标正常值及正常描述。
- 常用异常选项、异常程度、部位和补充文本。
- 是否支持一键全部正常、OD/OS分别正常和双眼结果复制。
- 病历描述输出顺序、正常描述格式和异常描述格式。
- 是否回传门诊病历及目标段落。

医技检查模板保留服务项目、PACS报告关联、指标外部字段映射和原始报告展示；结构化结果允许医生修订并保留原值与审计痕迹。

### 档案基线模板与治疗方案

档案基线模板组合多个检查模板；治疗方案选择一个档案基线模板。第一版内置“角膜接触镜基础档案基线模板”，但保留完整关联数据结构。

## 通用检查录入组件

组件输入包括检查模板ID、患者、就诊、使用场景、权限和既有检查实例。组件按模板及指标配置渲染数值、文本、单选、多选、布尔、OD/OS/OU或无眼别控件，并提供原始报告、异常提示和审计信息。

组件输出统一的检查实例，包含：

- 模板ID、模板版本及指标版本快照。
- 患者、就诊、来源场景、状态和记录时间。
- 结构化指标结果、原始接口值、人工修订值和修订痕迹。
- 原始报告引用。
- 根据模板规则生成的病历描述。

同一次就诊、同一检查模板原则上只形成一份检查实例。档案基线、专科病历和治疗复查引用同一实例；业务节点完成时各自保存引用或快照，避免重复录入和数据冲突。

## 眼健康检查快速录入

眼健康检查作为“医生查体”模板实现：

1. 新建检查时加载双眼正常值，但状态标记为“待医生确认”。
2. 提供“双眼全部正常、OD全部正常、OS全部正常、复制OD到OS、复制OS到OD”快捷操作。
3. 每个部位显示正常/异常状态；选择异常后紧邻展开常用异常、部位、程度和补充描述。
4. 医生确认保存前展示生成的门诊病历文本预览。
5. 双眼结果相同可以合并输出“双眼”；不同时分别输出“右眼”和“左眼”。
6. 保存检查实例后立即回传门诊病历，并保留同步状态。

第一版眼健康检查包含眼睑、睑结膜、球结膜、上下泪小点、角膜、前房、虹膜、瞳孔、晶体、玻璃体、眼底/视网膜、眼位、眼球运动、眼压、眼球大小和其他。

## 病历描述生成与回传

模板配置维护指标输出顺序及正常/异常描述格式。系统根据结构化结果生成格式化文本，医生可预览；补充说明单独保存，不反向破坏结构化结果。

回传规则：

- 保存眼健康检查时立即同步至普通门诊病历的专科查体目标段落。
- 只更新由该检查实例生成的受控段落，不覆盖医生手工书写的其他内容。
- 重复保存采用同一检查实例ID幂等更新，不重复追加文本。
- 门诊病历已签署或锁定时不直接覆盖，返回“待病历修改”状态并提示医生按修改流程处理。
- 保存检查实例成功、病历回传失败时保留检查数据，标记“同步失败”，支持重试。
- 记录生成文本、同步时间、回传版本、操作人及失败原因。

## 场景与权限

- 门诊医生站：医生可从专科病历或档案基线进入检查录入组件并保存、回传。
- 档案基线：引用当次就诊检查实例，完成基线时保存模板、指标、报告及生成描述快照。
- 专科病历：按需添加检查模板，复用已存在的当次检查实例。
- 治疗复查：治疗节点按检查模板打开组件并形成新的复查实例。
- 专科人群管理：配镜师默认只读查看历次检查实例和档案快照。

## 异常与状态

- 检查状态：待录入、待确认、已暂存、已完成。
- 同步状态：未同步、同步中、已同步、同步失败、待病历修改。
- 支持无报告、报告仅PDF/图片、部分结构化结果、接口异常、人工修订、无权限、未保存退出和病历锁定。

## 验收重点

- 检查模板能够在档案基线和专科病历中调用同一录入组件。
- 同一次就诊的同一模板不会重复生成互相冲突的检查记录。
- 眼健康检查可用一键正常快速完成，异常项可按部位和程度选择。
- 结构化结果能够稳定生成与现有门诊病历顺序一致的文本。
- 保存后能够幂等回传门诊病历；失败不丢失检查结果并可重试。
- 基线保存历史快照，后续模板或门诊病历变化不覆盖历史档案。
