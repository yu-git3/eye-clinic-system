# 眼科原型全局抽屉与浮层统一设计

## 1. 背景与问题

眼科专科系统原型嵌入 HIHIS 外壳后，同时存在通用抽屉、基础档案抽屉、专科病历抽屉、检查报告编辑抽屉和眼科检查录入抽屉。当前实现混用 `fixed`、`absolute` 以及不同模块私有层级，导致部分抽屉受到父容器裁切、顶部标签栏或其他浮层遮挡。

本次调整只统一抽屉与浮层的展示基础设施，不改变各模块的业务字段、操作按钮、保存规则及数据逻辑。

## 2. 最终确认口径

1. 所有业务抽屉均作为全局浮层展示，覆盖整个浏览器可视区域。
2. 抽屉打开时，遮罩覆盖系统顶部蓝色标签栏、左侧功能菜单和业务内容区。
3. 抽屉始终位于遮罩上方，不受工作台、模块容器、滚动区域或 `overflow` 裁切。
4. 抽屉头部和底部操作栏固定，中间内容区独立滚动。
5. 抽屉之上的选择器、确认框、打印预览和报告预览使用更高的统一层级。
6. 确认框的二次遮罩不得使确认框或抽屉内容出现异常变暗、被遮挡或无法操作。

## 3. 覆盖范围

需要纳入统一规则的页面与组件：

- 临床指标定义：新增、编辑、查看抽屉。
- 检查模板配置：新增、编辑、查看抽屉。
- 门诊医生工作台／基础档案：建立档案、编辑基本档案抽屉。
- 专科病历：新建、编辑专科病历抽屉。
- 检查报告：结构化结果编辑抽屉。
- 眼科检查组件：检查结果录入抽屉。

同时检查其上层浮层：

- 指标选择、科室选择、服务项目选择等选择器。
- 未保存退出确认、启停确认等确认框。
- 原始报告 PDF／图片预览。
- 档案打印预览、趋势分析等大型弹窗。

## 4. 技术设计

### 4.1 渲染方式

新增统一的全局抽屉浮层组件或挂载容器，通过 React portal 渲染到 `document.body`。业务模块只负责传入抽屉内容、关闭行为和可访问名称，不再依赖模块自身 DOM 层级。

遗留模块允许在不改业务 JSX 的前提下逐步接入同一基础组件，但最终生成的遮罩和抽屉都必须位于全局挂载层。

### 4.2 层级规范

采用固定层级令牌：

| 层级 | 用途 |
|---|---|
| 1000 | 一级全局遮罩 |
| 1001 | 一级业务抽屉 |
| 1100 | 抽屉之上的二级遮罩 |
| 1101 | 选择器、普通弹窗、趋势分析、原始报告预览、打印预览 |
| 1200 | 未保存退出、危险操作等最终确认框遮罩 |
| 1201 | 最终确认框 |
| 1300 | 全局消息提示 |

禁止各业务模块继续新增相互冲突的任意 `z-index`。

### 4.3 布局与滚动

- 全局抽屉：`position: fixed; inset: 0 0 0 auto`。
- 抽屉宽度继续使用各模块现有宽度；窄屏时不超过 `100vw`。
- 抽屉整体使用纵向 flex 布局，头部和底部 `flex: none`，正文 `flex: 1; min-height: 0; overflow: auto`。
- 页面背景滚动在抽屉打开期间不可影响抽屉位置。
- 所有固定底部按钮必须完整可见，不与浏览器底部或正文内容重叠。

### 4.4 交互与可访问性

- 抽屉使用 `role="dialog"`、`aria-modal="true"` 和明确的 `aria-label`／标题关联。
- 打开后焦点进入抽屉；关闭后返回触发按钮。
- 一级遮罩是否关闭抽屉沿用各模块现有业务规则。
- 二级选择器或确认框打开时，只允许操作当前最高层浮层。
- `Esc` 优先关闭当前最高层浮层，不越级关闭底层抽屉。

## 5. 测试与验收

### 5.1 自动化测试

- 页面结构测试：所有目标抽屉必须使用统一全局挂载机制或全局抽屉组件。
- 样式测试：层级令牌顺序正确，专科病历抽屉不再使用 `position:absolute`。
- 回归测试：现有保存、取消、未保存确认、选择器和打印预览测试继续通过。
- 完整运行模型测试、页面测试及生产构建。

### 5.2 浏览器验收

在 HIHIS 外壳中逐一打开六类抽屉，确认：

1. 遮罩覆盖顶部标签栏、左侧菜单和内容区。
2. 抽屉完整显示且不被裁切、变暗或遮挡。
3. 头部、底部按钮持续可见，正文可独立滚动到底。
4. 在抽屉内打开二级选择器、确认框、打印预览或报告预览，层级正确。
5. 关闭二级浮层后仍停留在原抽屉，内容和滚动状态不丢失。
6. 在常用桌面宽度和窄屏宽度下均无横向溢出导致的关键按钮不可见。

## 6. 非范围

- 不重做业务页面视觉风格。
- 不修改抽屉中的字段、排序、校验和保存逻辑。
- 不调整外部嵌入的“OK镜治疗管理”和“人群管理+治疗方案配置0722”HTML内部浮层；仅保证其外层入口不与本系统全局抽屉冲突。

## 7. 自检结论

- 无待定项或占位符。
- 覆盖范围、层级、滚动、键盘与验收口径一致。
- 本次属于公共浮层基础设施修正，可在一个实施计划内完成。
